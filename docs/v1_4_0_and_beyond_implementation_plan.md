# Meta Description Generator v1.4.0以降 実装ロードマップ

## 1. 目的

v1.4.0以降では、次の順序でアプリケーションを発展させる。

1. Gemini API連携を最新の保守可能な構成へ移行する
2. Webページ取得と一括処理の安全性・信頼性を高める
3. SEO監査と生成品質評価を追加し、実務での判断を支援する
4. 大規模サイトで継続利用できるジョブ管理・履歴管理へ拡張する

既存の通常生成、一括生成、テンプレート、履歴、CSV出力との後方互換性を維持し、各バージョンを単独でリリース可能な単位に分ける。

# v1.4.0: Gemini基盤の刷新

## 3. リリース目標

Geminiモデルのハードコーディングを解消し、ユーザーが利用可能なモデルを選択できるようにする。同時に、旧Gemini SDKと壊れやすいJSON解析を置き換え、以降の機能追加に耐えられるサービス層とテスト基盤を整える。

## 4. 実装範囲

### 4.1 Google GenAI SDKへの移行

- `google-generativeai` から `google-genai` へ移行する
- `genai.configure()` によるグローバル状態を廃止する
- APIキーごとにクライアントを生成する
- Gemini通信を `GeminiService` に集約する
- 通常生成、修正生成、モデル一覧取得で共通のエラー変換を使用する
- `requirements.txt` に互換バージョン範囲を設定する

想定する新規ファイル:

- `services/gemini_service.py`
- `models/generation.py`
- `models/settings.py`

### 4.2 モデル選択機能

生成画面のAPIキー欄付近に以下を追加する。

- 使用モデルのドロップダウン
- 「モデル一覧を更新」ボタン
- モデルIDを直接入力できる上級者向け入力
- 現在選択中のモデルIDと区分（安定版／プレビュー等）の表示

モデル一覧はGemini APIから取得し、`generateContent` を利用可能なモデルだけを候補にする。取得結果はセッション中にキャッシュする。

動作方針:

- 初回起動時はアプリ既定モデルを選択する
- 最後に正常利用できたモデルを保存する
- 保存済みモデルが利用不可なら再選択を案内する
- 利用不可時に別モデルへ暗黙に切り替えない
- 通常生成、一括生成、修正生成で同じ選択値を使用する
- テンプレートへのモデル保存は任意設定とし、既定ではアプリ共通設定として扱う

### 4.3 構造化出力とデータ検証

- GeminiのStructured Outputsを使用する
- `title`、`title_tag`、`description` を必須フィールドにする
- 提案数が3件であることを検証する
- 空文字、型不正、フィールド欠落を拒否する
- タイトルとdescriptionの文字数を検証する
- 不正な応答は1回だけ修復または再生成する
- ユーザー向けエラーと診断用エラーを分離する

`controls[9]` のようなUI位置依存を廃止するため、生成結果カードをクラス化し、値の取得・更新を名前付きメソッドへ移す。

### 4.4 履歴と手動編集の整合性

- 履歴エントリに一意なIDを付与する
- 使用モデルを履歴へ保存する
- 「生成直後の初稿」と「ユーザーが確定した結果」を区別する
- 手動編集またはAI修正後に「履歴へ反映」できるようにする
- CSVへモデル名と結果状態を追加する
- 既存履歴データを読み込めるよう、欠損フィールドに既定値を設定する

### 4.5 設定スキーマ

設定にスキーマバージョンを追加する。

```json
{
  "schema_version": 2,
  "gemini_model": "選択されたモデルID",
  "model_selection_mode": "list",
  "last_verified_at": "ISO 8601日時"
}
```

移行処理は冪等にし、複数回起動しても既存データを壊さないこと。

### 4.6 不要・重複コードの整理

- 未完成の共通修正ダイアログを削除または正式実装する
- Gemini通信を `core_logic.py` からサービスへ分離する
- UIから直接Gemini SDKを参照しない
- `test_model.py` を実APIスモークテストへ整理する
- README内のモデル名とSDK記述を実装に合わせる

## 5. v1.4.0受け入れ条件

- ユーザーがモデルを選択して通常生成できる
- 同じモデルが一括生成と修正生成にも使用される
- モデル選択がアプリ再起動後も復元される
- 廃止・権限不足・存在しないモデルで理解可能なエラーが表示される
- Gemini応答に余計な文章が含まれても、構造化出力経由で安定して処理できる
- 手動編集または修正生成した内容を履歴とCSVへ反映できる
- 既存の履歴とテンプレートが消失しない
- すべての単体テスト、起動テスト、パッケージ版スモークテストが成功する

## 6. v1.4.0テスト計画

### 自動テスト

- モデル一覧のフィルタリング
- モデル設定の保存・復元・旧設定移行
- 通常、一括、修正生成へのモデルID伝播
- 構造化出力の正常、欠損、型不正、件数不正
- 履歴ID、モデル名、編集後更新
- Gemini API例外からアプリ例外への変換
- モックを使用したAPI非依存テスト

### 手動・結合テスト

- 実APIキーによる安定版モデルでの生成
- プレビューモデル選択時の生成
- 無効なモデルIDの入力
- APIキー変更後のモデル一覧再取得
- `.exe` 化したアプリでの設定保存と再起動

実APIテストは通常のテストスイートから分離し、環境変数で明示的に有効化する。

## 7. v1.4.0対象外

- URLの並列クロール
- サイトマップ取り込み
- 複数モデルの同時比較
- 本格的なSEO監査

これらは後続リリースで扱う。

# v1.5.0: Web取得と一括生成の堅牢化

## 8. リリース目標

任意URLを安全かつ安定して取得し、一括処理を途中で制御・再実行できるようにする。

## 9. 実装範囲

実装上の入力予算は、モデル固有の上限を推測して最大まで使用するのではなく、
日本語を保守的に見積もる推定トークン数で上限を設定する。実トークン数はモデルや
トークナイザーにより異なるため、上限保証ではなく過大入力を避ける安全側の予算として扱う。

### 9.1 URL検証

- `http` と `https` のみ許可する
- ホスト名、ポート、URL長を検証する
- localhost、ループバック、プライベート、リンクローカル、予約済みIPを既定で拒否する
- DNS解決結果とリダイレクト先を毎回検証する
- 認証情報を含むURLを拒否する
- 必要な場合だけ、上級者設定でプライベートネットワークを明示許可する

### 9.2 HTTP取得制限

- 接続と読み取りのタイムアウトを分離する
- 最大レスポンスサイズを設定する
- HTML/XHTML以外を拒否する
- ストリーミング取得を使用する
- リダイレクト回数を制限する
- 429、502、503、504を再試行対象にする
- `Retry-After` と指数バックオフを使用する

### 9.3 本文抽出精度

- `main`、`article` を優先する
- `h1`〜`h3`、`p`、`li`、必要な表データを抽出する
- `nav`、`footer`、Cookie告知などの定型文を除去する
- canonical、robots、OGP、言語、JSON-LDを取得する
- Product、Article、FAQなどの構造化データを要約対象へ追加する
- 重複段落を除去する
- 文字数ではなくモデルの入力上限を考慮した予算管理を行う
- Web本文を信頼できないデータとしてプロンプト内で分離する

### 9.4 一括生成の運用改善

- キャンセルボタン
- URLごとの状態表示（待機、取得中、生成中、成功、失敗、キャンセル）
- 失敗URLだけの再実行
- 固定1秒待機をレート制御へ置き換える
- 成功結果をURLごとに即時保存する
- 終了時に成功・失敗・スキップ件数を表示する

## 10. v1.5.0受け入れ条件

- 非HTTP URLと危険なローカルアドレスが取得前に拒否される
- 大容量レスポンスでアプリのメモリ使用量が無制限に増えない
- リダイレクト先も同じ安全性検証を通る
- 一括生成をユーザーが途中でキャンセルできる
- 429/503後に規定回数再試行し、最終結果がURL単位で記録される
- 失敗したURLだけを再実行できる

# v1.5.1: Windows配布サイズの初期最適化

## 10.1 リリース目標

開発環境にだけ必要なライブラリをWindows実行ファイルへ混入させず、
v1.5.0の102,664,931 bytesから少なくとも10%削減する。

## 10.2 実装範囲

- `.venv-build/` にリリース専用の隔離環境を作成する
- Flet、PyInstaller、実行時依存と推移的依存のバージョンを固定する
- 実行時に不要なCLI、表示補助、ビルド用モジュールを段階的に除外する
- exeの容量、除外モジュール、製品・ファイルバージョンを自動検証する
- 手動のDLL削除、UPX、Fletのメジャーなビルド方式変更は後続段階へ送る

## 10.3 受け入れ条件

- 最終exeが90,000,000 bytes以下で、v1.5.0比10%以上の削減を満たす
- 除外対象モジュールがPyInstallerアーカイブに収録されていない
- 単体・結合・起動テストと、パッケージ版の起動スモークテストが成功する
- 実APIによる通常生成、設定保存、正常終了をリリース前に確認する

# v1.5.2: Windows配布サイズの重複最適化

## 10.4 リリース目標

v1.5.1で残ったFletランタイムの二重収録を安全に解消し、
86,995,084 bytesから62,000,000 bytes以下へ削減する。

## 10.5 実装範囲

- テンプレートに出力言語（日本語・英語）を保存し、通常・一括・修正生成へ適用する
- 既存テンプレートは出力言語を日本語として後方互換で読み込む
- 固定の日本語要件とサイト共通の指示が競合しないプロンプトに変更する
- exe直下と`flet_desktop/app/flet/`配下のファイルをサイズとSHA-256で比較する
- 正規配置側を維持し、内容が一致する許可済みFlet固有DLLのルート側だけを除外する
- Python側でも利用し得るCRT互換ファイルは一律削除しない
- 管理対象PyInstaller specでAnalysis後、CArchive生成前に除外する
- Flet固有重複、残存重複容量、正規配置、総容量を自動検証する
- メディアランタイムの完全削除、UPX、Fletアップグレードは対象外とする

## 10.6 受け入れ条件

- テンプレートの出力言語が保存・復元され、すべての生成経路で同じ言語が指定される
- 既存テンプレートを読み込んだ場合は日本語が選択される
- 最終exeが62,000,000 bytes以下で、v1.5.1比28%以上の削減を満たす
- 許可対象のFlet固有ルート重複と`*_plugin.dll`重複が残っていない
- 意図的に維持するルート／Flet重複の圧縮後合計が1,000,000 bytes以下
- Fletランタイムの正規配置側ファイルが維持されている
- 全品質ゲートとパッケージ版の起動・生成・保存・正常終了が成功する

# v1.6.0: SEO品質支援

## 11. リリース目標

生成するだけでなく、既存ページの問題を可視化し、提案を比較・選択できるSEO支援ツールへ拡張する。

## 12. 実装範囲

### 12.1 ページSEO監査

- titleとdescriptionの欠落、長さ、重複候補
- H1の欠落・複数存在
- canonicalとrobotsの状態
- ページ言語
- OGPの欠落
- 構造化データの有無
- 監査項目を「エラー」「警告」「情報」に分類

### 12.2 生成品質スコア

- ページ本文との関連性
- 必須キーワードの充足
- 3案間の類似度
- タイトルとdescriptionの重複
- 文字数または表示幅
- 禁止語・除外語

スコアだけで合否を決めず、根拠と改善候補を併記する。

### 12.3 サイトマップ・CSV入力

- `sitemap.xml` とサイトマップインデックスの読み込み
- CSVからURLとページ固有キーワードを読み込み
- 対象URLの選択、除外、重複排除
- robots.txtによるクロール可否の表示
- 最大件数と処理見積もりの事前表示

### 12.4 SERPプレビュー改善

- 単純な文字数に加えて推定ピクセル幅を表示する
- デスクトップ／モバイル表示を切り替える
- titleとdescriptionの省略位置を可視化する
- プレビューは目安であり、実際のGoogle表示を保証しない旨を表示する

### 12.5 編集機能

- タイトルのみ再生成
- descriptionのみ再生成
- タイトルとdescriptionのセット再生成
- 「短く」「具体的に」「ブランド名を追加」などのクイック修正

## 13. v1.6.0受け入れ条件

- URL取得後にSEO監査結果と生成案が同じ画面で確認できる
- 品質スコアに判定根拠が表示される
- サイトマップから選択したURLだけを一括処理できる
- ページ別キーワードをCSVから渡せる
- タイトルとdescriptionを個別またはセットで再生成できる

# v1.7.0: 大規模運用と高度機能

## 14. リリース目標

数十〜数百ページ規模の継続運用、比較検証、結果の監査に対応する。

## 15. 実装範囲

### 15.1 永続ジョブ

- 一括生成をジョブとして保存する
- アプリ終了後も完了済み・未処理URLを識別する
- 中断地点から再開する
- ジョブ単位でCSV出力・削除する
- 同一URLの再実行ポリシーを設定する

### 15.2 上限付き並列処理

- URL取得とGemini生成を別キューにする
- 同時実行数をユーザー設定可能にする
- モデル別レート制限を適用する
- キャンセルとシャットダウンを安全に処理する

### 15.3 モデル比較

- 同一入力を2つ以上のモデルへ送信する
- 出力、所要時間、トークン使用量、概算コストを比較する
- ユーザーが採用結果を選択する
- 比較処理前にAPI呼び出し回数増加を明示する

### 15.4 履歴バージョン

- 初稿、AI修正、手動修正、確定版を時系列保存する
- 差分表示と以前の版への復元
- 採用・却下・保留ステータス
- 変更理由のメモ

### 15.5 資格情報保護

- Windows Credential ManagerなどOSの資格情報ストアを利用する
- APIキーを保存しないモード
- 保存済みAPIキーの削除
- ログと例外メッセージから秘密情報を除去する

### 15.6 エクスポート拡張

- CSV列のカスタマイズ
- ジョブ単位のJSON出力
- CMS取り込み用の列マッピング
- 既存メタデータと提案の差分出力

## 16. v1.7.0受け入れ条件

- 中断した一括ジョブを再起動後に再開できる
- 設定された同時実行数とレート制限を超えない
- モデル比較の追加コストが実行前に明示される
- 生成結果の変更履歴を復元できる
- APIキーをOS資格情報ストアへ保存または保存せず利用できる

## 17. 横断的なアーキテクチャ方針

依存関係を次の向きに限定する。

```text
UI
 ├─ Application / Use Cases
 │   ├─ GeminiService
 │   ├─ WebsiteFetchService
 │   ├─ SeoAuditService
 │   └─ HistoryService
 └─ Models

Infrastructure
 ├─ Google GenAI SDK
 ├─ HTTP client
 ├─ Flet client_storage
 └─ OS credential store
```

- UIはSDKやHTTPライブラリを直接呼ばない
- サービスはFletコントロールを参照しない
- 外部API応答をそのままUIへ渡さず、アプリ内モデルへ変換する
- エラーはカテゴリ化し、文字列検索だけに依存しない
- 保存データにはスキーマバージョンを持たせる
- 長時間処理にはキャンセル経路を用意する

8. README、CHANGELOG、設定移行手順が更新されている
9. パッケージの容量、除外モジュール、バージョン情報の自動検証が成功する

推奨テスト構成:

```text
tests/
 ├─ unit/
 ├─ integration/
 ├─ fixtures/
 ├─ test_startup.py

```

## 20. 主なリスクと対策

| リスク | 影響 | 対策 |
| :--- | :--- | :--- |
| モデルの廃止・名称変更 | 生成不能 | APIから候補取得、選択状態の検証、明示的な再選択 |
| SDK移行による挙動差 | 回帰不具合 | モックによる契約テスト、旧実装との比較テスト |
| モデルごとの構造化出力差 | JSON処理失敗 | 対応能力の確認、アプリ側バリデーション、限定再試行 |
| 保存データ形式変更 | 履歴・設定消失 | スキーマバージョン、冪等な移行、移行前バックアップ |
| URL検証の誤判定 | 正当なサイトを取得不可 | 理由表示、明示許可設定、境界値テスト |
| 一括処理のAPI費用増加 | 想定外の費用 | 実行前件数表示、上限設定、キャンセル、モデル比較時の警告 |
| PyInstallerと新依存の相性 | 配布版のみ起動不能 | 各リリースでパッケージ版スモークテスト |

## 21. 最初の着手単位

最初の開発単位は、v1.4.0のうち以下を1つの機能ブランチで実施する。

1. `pytest` とGeminiモックの導入
2. `google-genai` への移行
3. `GeminiService` の追加
4. モデルIDを引数として通常生成できるところまで実装

この段階ではUIへモデル一覧を追加せず、テストでモデル伝播と構造化出力を確立する。その後、モデル選択UI、一括生成、修正生成、履歴移行を小さな変更単位で追加する。
